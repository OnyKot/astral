# Legal Hold Policy

This document describes the neutral compliance and anti-abuse controls available in `astral_api`.

## Purpose

The legal hold layer is intended for:

- regional compliance controls backed by documented policy
- risk-based access handling
- dry-run review before rollout
- auditable decisions with request identifiers

It is not intended for ad hoc hard-coded country discrimination in application code.

## Enforcement Modes

The middleware supports four actions:

- `allow`: request passes through normally
- `warn`: request passes through and receives a compliance notice header
- `challenge`: request is stopped and receives a structured verification-required response
- `block`: request is stopped and receives a structured unavailable-in-region response

`warn`, `challenge`, and `block` decisions are logged with:

- `requestId`
- `ip`
- `path`
- `method`
- `countryCode`
- `ruleId`
- `reason`
- `action`
- `dryRun`
- `policy`

## Rollout Order

Use this order. Do not skip straight to `block`.

1. `enabled=true`, `dryRun=true`, `defaultAction=allow`
2. add narrow rules
3. review logs for false positives
4. move selected rules to `warn`
5. move selected rules to `challenge`
6. use `block` only after policy review

## Environment Variables

| Variable | Meaning |
| --- | --- |
| `ASTRAL_LEGAL_HOLD_ENABLED` | Turn middleware on/off |
| `ASTRAL_LEGAL_HOLD_DRY_RUN` | Log matches without enforcing |
| `ASTRAL_LEGAL_HOLD_DEFAULT_ACTION` | Default action when no rule matches: `allow` or `warn` |
| `ASTRAL_LEGAL_HOLD_POLICY_NAME` | Human-readable policy label for logs |
| `ASTRAL_LEGAL_HOLD_SUPPORT_URL` | Link shown on HTML denial page |
| `ASTRAL_LEGAL_HOLD_EXEMPT_PATHS` | Comma-separated path prefixes excluded from evaluation |
| `ASTRAL_LEGAL_HOLD_ALLOW_COUNTRIES` | Comma-separated ISO country codes explicitly allowed |
| `ASTRAL_LEGAL_HOLD_WARN_COUNTRIES` | Comma-separated ISO country codes to warn |
| `ASTRAL_LEGAL_HOLD_CHALLENGE_COUNTRIES` | Comma-separated ISO country codes to challenge |
| `ASTRAL_LEGAL_HOLD_BLOCK_COUNTRIES` | Comma-separated ISO country codes to block |

## Safe Default Policy

Recommended starting point:

```env
ASTRAL_LEGAL_HOLD_ENABLED=true
ASTRAL_LEGAL_HOLD_DRY_RUN=true
ASTRAL_LEGAL_HOLD_DEFAULT_ACTION=allow
ASTRAL_LEGAL_HOLD_POLICY_NAME=regional-compliance-review
ASTRAL_LEGAL_HOLD_SUPPORT_URL=https://astraof.com/help
ASTRAL_LEGAL_HOLD_EXEMPT_PATHS=/_health,/status/summary,/v1/status/summary,/_rpc,/webhooks/livekit
ASTRAL_LEGAL_HOLD_ALLOW_COUNTRIES=
ASTRAL_LEGAL_HOLD_WARN_COUNTRIES=
ASTRAL_LEGAL_HOLD_CHALLENGE_COUNTRIES=
ASTRAL_LEGAL_HOLD_BLOCK_COUNTRIES=
```

## Recommended Neutral Rules

Use documented policy and operational signals. Prefer these over broad country lists:

- datacenter or hosting-provider ASN review
- VPN / proxy / Tor risk sources
- abusive registration or login bursts
- repeated challenge failures
- legal review of specific compliance requirements

## Response Shapes

### HTML browser request

For `GET` requests that prefer `text/html`, the middleware renders a simple user-facing page with:

- short message
- support link
- request ID

### JSON/API request

For API traffic, the middleware responds with structured errors:

- `SERVICE_UNAVAILABLE_IN_REGION`
- `LEGAL_HOLD_CHALLENGE_REQUIRED`

The response also includes:

- `legal_hold.action`
- `legal_hold.country_code`
- `legal_hold.rule_id`
- `legal_hold.reason`
- `legal_hold.request_id`

## Operational Notes

- Request IDs are generated by `RequestIdMiddleware` and echoed in `X-Request-Id`.
- Exempt paths should always include health and internal webhook endpoints.
- Keep `MAXMIND_DB_PATH` configured if country-based rules are used.
- Run new policies in `dryRun=true` first.
